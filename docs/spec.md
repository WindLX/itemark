# Itemark 需求规格

## Problem Statement

项目工作、事实与术语分散在会话、临时笔记和人工交接里，新会话难以可靠判断目标、进展、阻塞和依据。团队需要一套人和 AI 都能使用的本地记录工具，让已登记的内容可查、可维护，工作事项也能继续推进。Itemark 不承担 AI 长期记忆或完整对话归档。

## Solution

提供一个本地 CLI，原生管理工作事项、事实与术语。记录采用人和 AI 都能使用的本地文件，并支持现场查询及按需生成带来源和时点的总览或交接。本仓库作为首个验证项目，已由 Itemark CLI 接管自有记录；适配情况见 [v0 记录适配说明](v0-adaptation.md)。

## User Stories

1. 作为项目成员，我想管理工作事项、事实与术语，以便把后续工作所需的信息留在可查、可维护的项目记录中。
2. 作为项目成员，我想通过项目范围内唯一的稳定 ID 查找或移动记录，以便路径变化和跨 group 移动都不改变身份。
3. 作为项目成员，我想查看工作事项状态、事实核实情况、进展、决策和可复用证据，以便理解记录当前表达的内容。
4. 作为项目成员，我想表达父子关系和前置依赖，以便区分工作归属与执行顺序；子项完成后，父项仍按自己的验收条件判断。
5. 作为项目成员，我想废弃或恢复任一记录并保留原 ID 与历史，以便更正和后续恢复都可追溯。
6. 作为项目成员，我想在工作事项完成时看到完成说明以及证据或明确的未验证说明，以便不把“完成”误认为“已验证”。
7. 作为新会话中的 AI，我想从项目入口先检查已有事项和摘要，再按需读取事项详情，以便只恢复已记录的工作，不臆测缺失历史。
8. 作为项目成员，我想按需生成标明来源和时点的总览与交接，以便快速看清进行中、阻塞、完成但未验证和下一步。
9. 作为项目成员，我想编辑事项正文时保留原有 Markdown 内容与顺序，以便 CLI 的定向更新不会重排或覆盖我的文字。
10. 作为脚本或自动化调用方，我想选择机器可读的 JSON 呈现，并通过非零退出状态识别错误，以便在不改变操作语义的情况下处理结果。
11. 作为同时使用多个 CLI 的项目成员，我想让并发事项写入不丢失、ID 不重复，并让同一事项冲突显式失败，以便发现冲突后可以安全处理。
12. 作为 Itemark 的维护者，我想先用手工记录验证入口、工作事项与交接，再让 CLI 接管记录，以便设计来自实际使用。
13. 作为项目成员，我想建立和查看一级 group，并将记录移动到另一个 group，以便按项目需要组织混合 kind 的记录，同时保留项目 ID。
14. 作为项目成员，我想通过 ID 引用其他 group 的记录而不复制记录，以便跨组引用保持唯一来源。
15. 作为项目成员，我想用自定义 kind 的模板和字段约束组织记录，并检查必填章节与字段，以便保持内容结构清楚。

## Implementation Decisions

- 使用单个 Rust crate 实现同步 CLI，以职责清楚的普通函数组织行为。依赖成熟 crate 来处理通用格式，保持接口清楚、实现直接；简单性不以依赖数量衡量。不预设 trait、异步执行或插件架构。依赖方向为 Clap、Serde、TOML 解析，以及候选 YAML/Markdown 解析和 stderr 日志库；不锁定具体版本。文件锁使用标准库能力，不额外引入锁 crate。
- 每条记录由 YAML 头部和 Markdown 正文组成；其记录文件是权威来源，ID 独立于文件路径。使用成熟 YAML 库，不自行实现伪 YAML 解析。工作事项、事实与术语均通过项目自定义 kind 管理。
- 所有记录共享项目范围内唯一的稳定 ID、按 ID 引用、历史更正，以及保留 ID 和历史的废弃/恢复生命周期。恢复时保留废弃前适用的业务状态，不重置为进行中。每条记录恰属一个一级 group；group 可混合 kind、不嵌套。跨组移动保留 ID，跨组引用按 ID 指向原记录，不复制记录。
- 工作事项业务状态为待办、进行中、阻塞、完成；`dropped` 属于所有记录共享的废弃生命周期，不是工作业务状态。事实核实可有自己的状态，术语不要求工作业务状态。
- Kind 通过项目配置和 Markdown 模板维护。自定义 kind 声明名称、说明、模板及少量字段约束（必填、基本类型、枚举），也可声明必填 Markdown 章节。所有 kind 使用通用处理，不硬编码封闭的类型集合。CLI 提供 kind 查看和检查，不提供逐字段 kind 编辑器；章节检查只确认存在且非空，不解释语义、不强制顺序或排版。Kind 不定义任意程序行为、脚本或工作流。
- 路径方案建议由 `itemark.toml` 指定 Itemark root（相对 TOML 所在目录）；kind 模板引用 root 下的本地 Markdown 文件（相对 root），不依赖运行时当前目录。此为工程推荐草案，字段名和最终解析规则尚未冻结。
- Kind 可选声明完成字段和值（配置名暂作草案）。只有显式配置且写入完成值时，CLI 才强制要求非空的完成说明，以及证据引用或未验证说明；`check` 执行相同规则。未声明时不应用此固定完成检查；事实核实不会自动完成工作事项。
- AI 修改 kind 或其他规范中的重要决策前须向用户确认。
- CLI 更新已支持记录的结构字段、指定章节或 group 时保留用户正文，不重排整份文档。字段位置、允许的基础类型集合及章节配置格式仍待讨论。
- `add` 可按模板创建尚未填完的记录；必填字段或章节为空时不拒绝创建，`check` 报告缺项。字段提供非空值时检查基本类型和枚举。普通写入维护记录语法、ID 和引用完整性，但不自动运行整份内容检查。
- 每次查询都从当前记录现场构建查询索引；不使用数据库或持久查询缓存。可按需生成供人阅读的总览和交接摘要。
- 默认输出面向人的文本，可选 JSON 呈现；同一操作共享行为，只改变呈现方式。命令错误通过非零退出状态报告。
- `summary` 默认只输出当前总览，显式请求时才保存生成文件。
- 本库人读文档、模板、摘要和 CLI 提示默认简体中文（zh-CN）。命令名、ID、配置键和 JSON 字段保持稳定，不随语言设置翻译。
- 项目级 `itemark.toml` 记录事项目录、少量查询默认值和显式项目语言；可由命令行覆盖的配置项按 CLI 参数、项目配置、内置默认值取值。语言由项目配置控制，无 `--language` 覆盖参数；新项目 `init` 按系统 locale 选择初始值，缺少配置时默认 zh-CN。配置不设置工作流规则。
- 切换输出语言只改变呈现，不改变 kind 字段键、必填章节的匹配规则；已有模板和记录仍按各自明确定义检查。语言切换不自动改写或翻译既有记录。
- 本项目现有工作记录作为本地事项追踪器：功能规格作为父级需求，已批准的实现事项以稳定 ID 和依赖关系承接 tickets。不增加独立 triage 字段或 `ready-for-agent` 标签；具体约定见本地 issue-tracker 配置。

## Testing Decisions

- 测试应验证使用者从 CLI 观察到的行为，不绑定内部函数结构。
- 主要通过真实 CLI 和临时项目目录验证：记录读写、正文保留、文本与 JSON 呈现、错误退出状态、现场查询、派生总览、group 移动与跨组引用、kind 约束检查和约定的并发冲突行为。当前仓库以集成测试验证这些外部行为。
- 验证必填章节与字段缺失、非空字段类型/枚举、以及配置的完成值触发固定完成检查；无完成配置时不套用该检查。普通写入不运行整份检查。
- 仅在实际需要时补少量普通函数测试；不 mock 存储。

## Out of Scope

- 图形界面、完整对话归档、AI 长期记忆或任意领域的通用知识库；首期管理限工作事项、事实与术语。
- 首期修改 LZB 内容或全面抽取其规范；后续首次接入 LZB 时只迁移未完成事项及继续工作所需依据。
- 数据库、持久查询缓存、多后端框架、插件架构或异步 CLI。
- 自动翻译服务或完整国际化框架。
- 保证检测或阻止任意编辑器、脚本及其他不遵守 CLI 协作约定的并发写入。
- 创建或发布外部 issue tracker 中的任务；本项目使用自己的事项文档承接工作追踪。

## Further Notes

- 命令行为见 [CLI 参考](../.agents/skills/itemark/references/cli.md)，精确参数以当前 `itemark --help` 为准。配置 schema、字段位置、基础类型集合、JSON 数据形状及并发边界仍属工程约定，依赖版本可能更新。
- 本仓库早期手工 v0 记录已按 [适配说明](v0-adaptation.md) 接管；适配过程和兼容边界以该文档为准。工作事项完成依据要求仍有效。
- 完成字段和值配置为显式选择；未声明的 kind 不应用固定完成检查。Facts 核实不自动完成工作事项，术语不要求业务状态。
- 语言默认 zh-CN；项目语言配置决定既有项目的 CLI 固定文案，初始化时使用系统 locale 选择初始配置。语言切换不翻译或改写既有记录，不改变 kind 字段和章节检查规则。
- Itemark 的本地 issue tracker 映射和 Matt Pocock `to-spec`/`to-tickets` 覆盖规则记录在本地 issue-tracker 配置中；项目事项 ID 和依赖关系承接 tickets，不发布外部 issue。
- 陌生会话从项目入口读取总览，再按稳定 ID 查看相关记录；普通问答不自动登记为工作事项。
