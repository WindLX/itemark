# Establish the manual worklog baseline

## 目标

Create a small, human-editable Markdown worklog that can serve as its own first bootstrap project. Keep each work item in one Markdown file with a path-independent stable ID, a small YAML header, and fixed sections for goal, acceptance, current next step, history, and evidence.

## 验收

- [x] IDs are stable and independent of paths; one item is stored in one Markdown file.
- [x] Items use the five agreed status values, plus parent and dependency IDs.
- [x] Dropped items retain their IDs; corrections remain visible in history.
- [x] Completion records explain what was completed and provide evidence, or explicitly say what was not verified.
- [x] The index and handoff are summaries with source item IDs and a maintained-at time.
- [x] Records are clearly marked as manually maintained until a CLI can generate summaries.
- [x] The approach stays simple, avoids unnecessary abstractions, and does not claim tests or functionality that were not performed.
